# 验证记录

2026-11-04，首次源码发布准备。以下证据层分开记录，不把构建成功当作手机验收。

## 新整合代码

- `workflow_session.py`：整阶段复用一个 `Client`；全部计划/WAV 预检；精确锚点；选择后回读；先采音再播放；正常停止释放；每步原子断点；暂停/失败后不自动重放。
- `audio_injection_trial.inject_once`：复用单次注入逻辑，结束恢复调用方控制函数；上传失败也清理本次拥有的精确临时路径；已有他人文件不删除；策略释放必须有未注册状态。
- `target_audio_capture.py`：ready 文件原子发布，避免上层读到半写入 JSON。
- `usage_audit.py`：只输出指定日志时间段的 token 元数据，去重并核对累计差；计数重置/缺失事件拒绝估算。
- 运行时随源码提供，默认无需安装到个人技能目录；JDK 可由参数/JAVA_HOME/PATH 发现，MCP 配置只提供示例。

离线检查覆盖现有组件与上述异常路径。102 项 Python 主测试、5 项 dynamic Python 测试、3 项 JavaScript 测试均已通过；CI 另验证干净环境中的可运行性。

已在本机 JDK 21 / SDK 36 / Build Tools 36.0.0 实际构建 Android 控制 APK 与音频探针 JAR。APK v2/v3 签名验证通过，探针 JAR 为 7243 字节。使用本次构建专用测试密钥，没有读取/替换原设备使用的私钥，也没有安装到手机。

新 token 工具对历史执行会话的同一窗口复算出 357 次非重复更新、417802 未缓存输入、78351488 缓存输入、182765 输出，与既有审计一致。原始日志没有复制到仓库。

## 2026-11-11 口语实测与共享修复

沿用原有手机、应用和辅助服务，执行会话独占设备，优化会话仅改本地源码，在安全边界交接固定副本。本次使用 USB 控制；没有把本轮结果写成无线实测。

标准 scrcpy 副屏被主屏视频应用的 Presentation 窗口遮挡，原保护正确停止。基于固定 5.0.1 的最小补丁去掉 PUBLIC/PRESENTATION，新建私有副屏并直接迁移同一 U校园任务。新屏实际可读控件和画面、可录音，旧自有屏随后关闭；正式 scrcpy 安装未替换。补丁独立干净重建得到相同文件。迁移后厂商活动缓存仍指旧屏，保护改用无障碍目标焦点与 WindowManager 可见表面，并继续拒绝外来窗口。一次主屏告警来自显示分段解析错误，已用不依赖行首的解析纠正；没有可靠证据宣称迁移全程主屏焦点不变。

第一项 17 句范例暴露并修复了三个真实问题：副屏可见树不能代替完整句子清单；最后一行文字/按钮不能照搬旧 2400/2500 像素阈值；展开动画和音频准备后需要重新读取稳定标签。末句麦克风中心 y=2647 已按实际完整画面校准，仍验证完整标签、具体句子、187 像素偏移和录音像素。误差/遮挡时不发录音，持有的指针仍确保在同一副屏释放。

快速模式试验曾在 submitted 时立即切句。平台随后明确提示未完成，第 8–15 句没有保存，故该试验已撤回。最终路径保持不读数值分数，但先确认录音已提交并释放 UID 输入，再等待重录入口恢复，最后以阶段验收；只补平台明确缺失项。补齐后第一组实际进入复述。失败的快提交样本不作为提速成绩。
